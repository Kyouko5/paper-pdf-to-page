# paper-pdf-to-page

将 **一篇研究论文 PDF** 整理为 **一个详细、独立可读的 Markdown 论文解析页**，方便精读、复现评估以及 Introduction / Related Work 写作。源 PDF 保持原位、内容不变。

本目录提供的是供 AI 助手执行的 skill 指令，不是独立的 PDF 转换程序。实际执行规范见 [SKILL.md](SKILL.md)，界面显示信息和默认提示词见 [agents/openai.yaml](agents/openai.yaml)。

## 适用场景

- 精读一篇论文，梳理研究问题、系统建模、优化目标和约束。
- 理解算法流程、子问题分解、奖励或目标设计，以及论文报告的复杂度或收敛性。
- 核对实验类型、数据来源、运行平台、硬件和代码公开情况，判断复现还缺什么。
- 提取有依据的研究动机、研究空白、贡献与差异化比较点，用于后续论文写作。

默认不做多论文批处理、跨论文综合，也不生成概念页、主题页、对比页、索引、日志等配套文件。此类工作需要单独提出。

## 使用前准备

1. 让支持 skill 的 AI 助手加载本目录中的 `SKILL.md`。
2. 准备一个助手能够访问的研究论文 `.pdf` 文件，并明确指定该文件。
3. 确保助手具备可用的 PDF 解析或渲染工具，以及目标目录的写入权限。

本 skill 不绑定某个 PDF 工具，也不附带解析脚本。助手需要读取正文、元数据、图表、公式及必要的参考文献；重要系统图或实验表格在文本提取不清楚时，需要渲染相应页面进行核对。

如果工作区中有 `schema.md`，助手会先读取并遵循其中的论文页要求，同时保留“一篇论文只生成一个论文页”的范围。

## 快速开始

在支持 `$skill-name` 调用的助手中，可以直接使用以下提示词，将路径替换为真实路径。

### 基本用法

```text
使用 $paper-pdf-to-page 阅读 /absolute/path/to/paper.pdf，生成详细论文页。
```

### 指定输出目录

```text
使用 $paper-pdf-to-page 阅读 /absolute/path/to/paper.pdf。
将论文页保存到当前工作区的 notes/ 目录，文件名使用论文正式标题。
```

### 指定阅读重点和元数据

```text
使用 $paper-pdf-to-page 阅读 /absolute/path/to/paper.pdf。
重点解释优化问题的约束、算法的子问题分解和实验可复现性，保留重要数学符号。
frontmatter 中 tags 设置为 [resource-allocation, optimization]。
仍保留全部必需章节，论文未提供的信息请明确标记。
```

### 更新已有论文页

```text
使用 $paper-pdf-to-page 重新核对 /absolute/path/to/paper.pdf，
更新当前工作区中对应的论文页，补全实验证据卡片，保持 sources 中的原 PDF 路径不变。
```

若只指定了包含多篇 PDF 的文件夹，助手会先询问要处理哪一篇。每次调用应明确选中一个 PDF。

## 输出位置与文件名

输出路径按以下优先级确定：

1. 使用用户指定的路径。
2. 工作区已有 `wiki/` 目录时，使用 `wiki/<论文正式标题>.md`。
3. 否则使用 `<工作区>/<论文正式标题>.md`。

标题从 PDF 的正式论文标题中提取，修正换行和断词带来的问题，不仅凭 PDF 文件名判断。Markdown 一级标题保留完整论文标题；文件名使用对应的文件系统安全形式。

例如，工作区已有 `wiki/` 时：

```text
workspace/
├── papers/
│   └── paper.pdf                 # 原文件保持不变
└── wiki/
    └── Formal Paper Title.md    # 唯一的论文页输出
```

## 论文页包含什么

页面由 YAML frontmatter 和以下固定顺序的章节组成：

| 章节 | 内容要求 |
| --- | --- |
| 正式论文标题（H1） | 与 PDF 中的正式标题对应 |
| 单行摘要 | 简洁概括论文 |
| 题目驱动研究框架 | 梳理论文题目对应的研究框架 |
| Algorithm Design 快照 | 一段不超过 400 个汉字的中文，交代场景、研究对象、问题、具体方法和预期效果 |
| 图1系统框架草案 | 描述系统实体、任务或数据流、控制或优化变量、约束来源，供绘制系统图参考 |
| System Model | 实体、变量、目标、相关假设、约束和优化问题，保留重要符号 |
| Algorithm Design 详解 | 求解器或学习流程、子问题分解、目标或奖励设计、约束处理，以及论文报告的收敛性、复杂度和基线作用 |
| 实验证据卡片 | 验证方式、数据、平台、硬件、公开产物、复现判断和带条件的关键结果 |
| Introduction 写作素材 | 可复用的研究动机、研究空白与贡献点 |
| Related Work 写作素材 | 有依据的差异化比较点，避免泛泛评价 |

“图1系统框架草案”提供绘图所需的描述，默认不额外生成图片文件。各技术章节仅写到论文证据能够支持的程度。

### 实验证据卡片

该章节需要明确回答：

- **验证类型**：理论分析、仿真、轨迹驱动、仿真模拟（emulation）、原型或实地测试。
- **数据来源**：数据如何获得，是否有具名数据集。
- **平台与软件**：运行平台、框架和仿真器。
- **硬件与配置**：计算资源，以及论文涉及的 UAV、GBS、雷达等配置。
- **产物可用性**：代码、数据、配置是否可获取；无法确认时写明未知。
- **可复现性**：判断依据，以及具体缺失的材料。
- **关键结果**：报告结果时附上对应实验条件或比较基线。

## 元数据与证据规则

frontmatter 的完整字段模板见 [SKILL.md 的 Frontmatter 部分](SKILL.md#frontmatter)。字段覆盖标签、日期、来源、发表信息、文献用途、验证方式、实验环境和可复现性。

| 字段组 | 用途 |
| --- | --- |
| `tags`、`created`、`updated` | 标签与页面日期 |
| `sources` | 原始 PDF 的绝对路径；后续细化元数据时保持稳定 |
| `venue`、`venue_tier` | 发表场所和等级；不编造等级信息 |
| `literature_type`、`evidence_tier`、`paper_role`、`use_for` | 文献类型、证据定位及写作用途 |
| `validation_type`、`data_origin` | 验证方式与数据来源 |
| `platforms`、`frameworks`、`datasets`、`hardware_stack` | 实验平台、框架、数据集与硬件 |
| `artifact_availability`、`reproducibility_level` | 公开产物与可复现性 |

元数据取值优先级为：**用户明确指定的信息 → 论文明确提供的信息 → 保守默认值**。未知内容应明确标记，不把模板中的示例值当成论文事实。

正文需要区分三类信息：

- **论文报告的事实**：能在 PDF 中找到直接支持。
- **结构化解读**：根据论文公式或流程整理出的解释。
- **缺失证据**：标记为 `未说明` 或 `证据不完整`。

例如，论文只说“simulation results”，不能据此推断其使用了真实数据集、特定硬件、公开代码或实地验证。`sources` 必须指向原始 PDF，不能替换成虚构引用键或转换后的 Markdown 路径。

## 文件保护与验收

执行过程中不移动、复制、重命名、删除、批注或原位转换源 PDF。临时提取文件只能写入系统临时目录，使用后应清理。

完成后检查：

- 只创建或更新一个论文页文件，源 PDF 仍位于原路径且未被修改。
- 必需章节齐全，文件名与一级标题对应同一正式论文标题。
- 缺失证据已明确标记，关键实验结果保留条件或基线。
- 未额外创建跨论文页面或配套文件。
- 页面不依赖临时提取文件即可阅读。

## 常见问题

**可以一次处理多篇论文吗？**  
默认每次只处理一篇。可以逐篇调用；批处理或跨论文整理需要另行提出，不属于默认工作流。

**可以处理扫描版 PDF 吗？**  
取决于宿主是否提供 OCR 或页面视觉读取能力。本 skill 本身不附带 OCR 工具，无法读取的内容不能靠猜测补齐。

**论文没有代码、数据集或硬件说明怎么办？**  
保留对应字段或问题，标记未知、`未说明` 或 `证据不完整`，并在可复现性判断中列出具体缺项。

**会自动建立知识库或生成关系图吗？**  
不会。默认产物只有当前论文的 Markdown 页面，知识库扩展、关系图和其他配套产物需要单独请求。
