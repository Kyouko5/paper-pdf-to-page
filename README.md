# paper-pdf-to-page

将 **一篇 IEEE Transactions 或同等技术期刊论文 PDF** 整理为 **一个详细、独立可读的 Markdown 论文解析页**，用于精读、证据核查、复现评估以及 Introduction / Related Work 写作。该 skill 面向通信、计算机、控制、信号处理、AI/ML、能源、生物医学、制造、器件、测量等领域，不预设无人机、通信、任务卸载、能耗或某一种系统模型。

本目录提供的是供 AI 助手执行的 skill 指令，不是独立的 PDF 转换程序。实际执行规范见 [SKILL.md](SKILL.md)，界面显示信息和默认提示词见 [agents/openai.yaml](agents/openai.yaml)。

## 适用场景

- 梳理研究对象、问题定义、形式化模型、假设、目标、约束或理论命题。
- 理解算法、模型、网络、协议、系统架构、硬件流程、训练/推理、求解步骤或证明主线。
- 核对理论、仿真、公开数据、benchmark、原型、实验室、临床或真实部署证据，判断复现还缺什么。
- 提取有依据的背景、研究空白、研究问题、贡献、证据边界与可比较的 Related Work 轴。

默认不做多论文批处理、跨论文综合，也不生成概念页、主题页、对比页、索引、日志等配套文件。此类工作需要单独提出。

## 使用前准备

1. 让支持 skill 的 AI 助手加载本目录中的 `SKILL.md`。
2. 准备一个助手能够访问的研究论文 `.pdf` 文件，并明确指定该文件。
3. 确保助手具备可用的 PDF 解析或渲染工具，以及目标目录的写入权限。

本 skill 不绑定某个 PDF 工具，也不附带解析脚本。助手需要读取正文、元数据、图表、公式、证明、附录及必要的参考文献；重要架构图、曲线、实验表格或难以提取的公式需要渲染页面核对。

如果工作区中有 `schema.md`，助手会读取其中通用的论文页、证据、来源保护和元数据规范。schema 中针对特定领域的示例只在输入论文确属该领域时适用，不会强加给其他论文。

## 快速开始

### 基本用法

```text
使用 $paper-pdf-to-page 阅读 /absolute/path/to/paper.pdf，生成详细论文页。
```

### 指定阅读重点和元数据

```text
使用 $paper-pdf-to-page 阅读 /absolute/path/to/paper.pdf。
重点解释问题定义、方法核心机制、理论或实验依据以及可复现性，保留重要数学符号。
frontmatter 中 tags 设置为 [your-topic]，并根据论文实际类型填写 method_family、evaluation_metrics 或 theoretical_results。
```

### 更新已有论文页

```text
使用 $paper-pdf-to-page 重新核对 /absolute/path/to/paper.pdf，
更新当前工作区中对应的论文页，补全证据卡片，保持 sources 中的原 PDF 路径不变。
```

若只指定了包含多篇 PDF 的文件夹，助手会先询问要处理哪一篇。每次调用应明确选中一个 PDF。

## 输出位置与文件名

输出路径按以下优先级确定：

1. 使用用户指定的路径。
2. 工作区已有 `wiki/` 目录时，使用 `wiki/<论文正式标题>.md`。
3. 否则使用 `<工作区>/<论文正式标题>.md`。

标题从 PDF 的正式论文标题中提取，修正换行和断词带来的问题，不仅凭 PDF 文件名判断。Markdown 一级标题保留完整论文标题；文件名使用对应的文件系统安全形式。

## 论文页包含什么

页面由 YAML frontmatter 和以下固定顺序的章节组成：

| 章节 | 内容要求 |
| --- | --- |
| 正式论文标题（H1） | 与 PDF 中的正式标题对应 |
| 单行摘要 | 简洁概括论文 |
| 题目驱动研究框架 | 从标题抽取对象、问题、方法家族和主张，并核对正文主轴 |
| Algorithm Design 快照 | 方法导向的兼容标题；不超过 400 个汉字，说明设定、对象、问题/缺口、贡献或方法家族、核心机制和效果，不强求论文必须有算法 |
| 图1系统框架草案 | 泛化为系统、方法、流程、分类或证明依赖图，描述实体/组件、边界、输入输出、数据/信号/控制流、模块关系和评估路径 |
| System Model | 也用于 Problem Formulation；按适用性记录研究对象、变量、数据/信号、目标/指标、假设、约束、边界条件和形式化问题 |
| Algorithm Design 详解 | 方法导向的兼容标题；按论文实际内容解释算法、模型、网络、协议、架构、硬件流程、训练/推理、复杂度、理论保证、消融和基线 |
| 实验证据卡片 | 理论、仿真、数据集、benchmark、原型、实验室、临床或真实部署证据，以及复现判断 |
| Introduction 写作素材 | 背景、重要性、具体缺口、研究问题、贡献与证据边界 |
| Related Work 写作素材 | 按问题、假设、数据、方法、理论保证和验证等轴提取差异化比较点 |

不适用的字段写 `不适用（原因）`；论文应该说明但没有报告的字段写 `未说明` 或 `证据不完整`。不会为理论、综述、器件或测量论文凭空补造算法、系统实体或实验。

### 实验证据卡片

该章节按论文类型回答适用问题：

- **验证类型**：理论/证明、解析分析、数值仿真、合成数据、公开数据集或 benchmark、trace-driven、离线回放、emulation、实验室实验、原型、hardware-in-the-loop、用户研究、临床研究、实地测试、部署或文献综述。
- **数据来源**：数据集、样本量、划分、预处理，以及公开、专有、自采、真实测量、合成、借用或混合数据。
- **平台与配置**：软件、框架、仿真器、协议、仪器、实验室、临床/工业环境、设备、算力和运行条件。
- **评测细节**：指标、单位、基线、公平性、消融、敏感性、统计显著性、置信区间和不确定性（论文报告时）。
- **产物与复现**：代码、数据、配置、模型、测量设置的公开情况，以及具体缺失项。
- **理论证据**：定理/命题假设、结论、证明或验证路径。
- **关键结果**：附数据集或设定、指标和单位、比较基线，以及不确定性（若有）。

真实数据驱动不等于真实部署，仿真不等于 emulation，形式化保证也不等于经验观察。重要主张应尽量附上 section、page、figure、table 或 equation 定位。

## 元数据与证据规则

frontmatter 的完整字段模板见 [SKILL.md 的 Frontmatter 部分](SKILL.md#frontmatter)。除通用字段外，可按论文需要增加 `problem_domain`、`research_problem`、`method_family`、`contribution_types`、`evaluation_metrics`、`baselines`、`theoretical_results` 和 `limitations`。

`venue` 记录论文实际期刊名；不能因为期刊属于 IEEE Transactions 就推断 CCF、JCR 或其他等级，无法确认时将 `venue_tier` 写为 `Unknown`。`literature_type` 应按论文实际贡献填写，例如 `method`、`theory`、`system`、`empirical`、`benchmark`、`dataset`、`survey`、`application` 或 `unknown`。

正文需要区分三类信息：

- **论文报告的事实**：能在 PDF 中找到直接支持。
- **结构化解读**：根据论文公式、流程、架构、协议或证明整理出的解释。
- **缺失证据**：标记为 `未说明` 或 `证据不完整`，不能靠领域常识补齐。

## 文件保护与验收

执行过程中不移动、复制、重命名、删除、批注或原位转换源 PDF。临时提取文件只能写入系统临时目录，使用后应清理。

完成后检查：

- 只创建或更新一个论文页文件，源 PDF 仍位于原路径且未被修改。
- 必需章节齐全，并根据论文类型完成或标记不适用内容。
- 文件名与一级标题对应同一正式论文标题。
- 缺失证据已明确标记，关键数字包含指标和实验/理论条件。
- 理论、综述等非实验论文没有被强行填入伪造实验或硬件。
- 未额外创建跨论文页面或配套文件。
- 页面不依赖临时提取文件即可阅读。

## 常见问题

**可以一次处理多篇论文吗？**  
默认每次只处理一篇。可以逐篇调用；批处理或跨论文整理需要另行提出。

**理论论文没有系统模型或实验怎么办？**
保留统一章节，将 `Problem / System Model` 用于定义、假设和形式化问题，将方法详解用于定理、命题和证明主线；实验字段写 `不适用（纯理论论文）`，并记录理论证据。

**论文没有代码、数据集或硬件说明怎么办？**
如果该信息对论文类型应当适用，标记 `未说明` 或 `证据不完整`，并在可复现性判断中列出具体缺项；如果论文类型确实不需要该字段，写 `不适用（原因）`。

**会自动建立知识库或生成关系图吗？**
不会。默认产物只有当前论文的 Markdown 页面，知识库扩展、关系图和其他配套产物需要单独请求。
